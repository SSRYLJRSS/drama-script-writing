# 剧本撰写 Pitfalls 与教训汇总

> 本文档合并自多个实际项目的经验教训，按类别组织。所有项目名、路径、工具名已做通用化处理。
> 每条 Pitfall 保留：编号 + 标题 + 背景 + 教训 + 正确做法。

---

## 一、流程铁律类

### 1.1 【最大教训】禁止跳步
- **背景**：某职校实习压榨案项目，S1（发散搜索与选题）阶段。
- **教训**：S1 阶段不要输出 S3 的故事线设计。曾在 S1 确认前就甩出完整四幕糅合方案，用户回"感觉怪怪的，按步骤来，进入 S2"——方案本身不差，但步骤错了。
- **正确做法**：S1 只输出选题卡（案例素材表 + 推荐方向）。糅合方向可以提（如"多案例融合、四幕"），但具体幕结构、每幕糅合哪些案例留到 S3。

### 1.2 【S3 交付格式铁律：修改版必须落盘 + 聊天全文输出】
- **背景**：某东南亚绑架案项目，S3 故事线改稿时。
- **教训**：只输出"修改说明/片段"没贴全文、没保存到本地，用户当场点破："我看不到啊，你又没有保存到本地，也没有完整输出"。
- **正确做法**：每一版故事线（含修改版）必须①写入项目目录的故事线文件②聊天里贴**完整全文**（序幕 + 全部幕次 + 字幕 + 设计说明）。改一处也要整版输出。用户确认的是"看得见的全文"，不是改动摘要；只贴片段 = 等于没交付。

### 1.3 【每步等用户确认才进下一步】
- **背景**：通用流程铁律，所有项目适用。
- **教训**：用户说"就这样/开始/确认"才算当前步骤通过。没说确认词就擅自往下走，经常跑偏。
- **正确做法**：每一步输出后等用户确认信号。例外：用户口头给方向（如"以 XX 为主，再加一些其他事件"）等于选题已确认，可直接进 S2，不再等确认词（某追星悲剧项目实测）。

### 1.4 【每个项目新开对话，不跨项目混上下文】
- **背景**：同时处理多个项目时容易混线。
- **教训**：跨项目混上下文会导致素材/人名/数据串台。
- **正确做法**：每个项目新开对话，SOP 铁律。

### 1.5 【禁止修改用户的初步资料文件】
- **背景**：用户提供的项目初步资料是不可修改的原始素材。
- **教训**：擅自改动用户的初步资料会丢失原始信息，且用户无法溯源。
- **正确做法**：初步资料文件只读，所有补充和修改写到资料收集目录的新文件中。

### 1.6 【剧本必须保存到本地文件，不只是聊天窗口输出】
- **背景**：通用交付铁律。
- **教训**：只在聊天窗口输出剧本，用户无法保存和迭代。
- **正确做法**：剧本必须保存到项目目录的剧本生成文件夹中，同时聊天窗口也输出全文。

## 二、改编自由度类

### 2.1 【不要拿"真实性"当尺子删糅合细节】
- **背景**：某抚养欺诈案项目（多名子女非亲生），S5 自检阶段。
- **教训**：改编剧 = 多案例多角度糅合，"不必按照真实的来"。S5 自检时删掉了"两家机构/刷到旧新闻/婴儿体重"这些外围细节，被用户叫停恢复。
- **正确做法**：外围细节（鉴定机构数量、婴儿体重、刷到的新闻内容等）可自由重组编造，只要服务于情绪冲击。**唯一底线** = 判决结果、关键金额、案件定性不编不改（如具体赔偿金额、报告份数、字幕案例事实保持原样）。

### 2.2 【金额三口径铁律：索要价 ≠ 实付价 ≠ 卖人抽成】
- **背景**：某东南亚绑架案项目，用户骂"这个金额怎么可能全给她，你是傻逼吗"。
- **教训**：绑架案里同一笔钱有**三套口径，严禁混写**：
  - ① 向家属**索要的赎金**（如约 540 万人民币 ≈ 80 万美元，以官方通报/权威媒体口径为准）
  - ② 家属**实际支付的金额**（媒体口径"东拼西凑汇出 80 万"，不是索要的全额）
  - ③ 诱骗者/内线的**卖人抽成**（与赎金无关，她自己拿走的卖人钱）
- 初稿把索要价安到诱骗者抽成头上，用户直接开骂。
- **正确做法**：写任何金额前先问：这是索要价还是实付价还是抽成？三笔钱各归各。正确写法示例——施暴者："你是她卖的一单货。卖你的钱她早抽走了，你妈那边凑的赎金，是给我们的"；钱到账报实付数："钱到了。80 万，一分不少"。

### 2.3 【故事线确认 ≠ 细节可编，S5 自检必须回资料卡逐项核对】
- **背景**：某抚养欺诈案项目，定稿后发现 3 处硬伤。
- **教训**：写剧本时每处数字/机构/时间线都要回资料卡核对。剧本里每个数字/机构/事件问自己"资料卡里有吗？出处是哪个链接？"答不上来就删或改。
- **具体硬伤**：①序幕"四份报告，两家机构"是编造——实为**同一家**鉴定中心四次鉴定（不同日期分别做双胞胎/大女儿指甲/复核/头发样本）；②剧内引用的"刷到热搜新闻"必须时间合理——原稿引用的旧案已结案多年，当年再挂热搜不合理，改为真实细节；③编造细节数字（如"八斤"体重）无资料依据，必须删。
- **正确做法**：S5 自检时逐项回溯每个事实点的来源，无依据的删，有依据的核对是否准确。

## 三、序幕设计类

### 3.1 【序幕"炸裂" = 动作三连击，不是对话揭穿】
- **背景**：某东南亚绑架案项目，用户原话"序幕不行，要炸裂，就是下飞机被强制抓走，挨打，被交易。全部重新设计"。
- **教训**：第一版序幕用对话流（打电话 → 被带走 → 绑匪说"你闺蜜把你卖了"）被否。对话流不够"炸"，要有动作冲击力。
- **正确做法**：炸裂三要素——
  - ① **强制抓走**（围上 → 拧臂 → 捂嘴拖行，全程动作无废话）
  - ② **暴力 + 生理威胁拉满**（施暴者施暴动作具体到位，威胁感拉满）
  - ③ **验货不涉价**（"货到手了。人我验了，就是她"，电话那头"看好了别出岔子"）
- **序幕绝不出现赎金数字**——价格全部后移到后续幕次的家属线才爆。用户原话："刚开始序幕，不要涉及这个，就是验货那些剧情"。

### 3.2 【揭穿方式 = 羞辱式 + 逻辑链，不要保留上帝视角的模糊设计】
- **背景**：同上项目，序幕中受害者如何知道"被熟人出卖"。
- **教训**：初稿设计"货主不点破名字"——保留为观众懂她不懂的上帝视角，被否。用户要求当场揭穿。
- **正确做法**：受害者被打得蜷缩时**喊救命喊的是卖她的人**（"XX 救我！XX 救我啊！！"）→ 施暴者停手蹲下来，举着受害者手机（屏幕还亮着对方"落地了吗宝贝~"消息）怼到脸上"别指望她来救你，因为就是她把你卖了的"→ 施暴者**狂笑**收尾。揭穿后压抑点从"无知之死"变**"清醒之死"**：受害者知道了 → 想质问 → 对方已拉黑 → 赎金交了照样被杀——压抑 = 知道真相也救不了自己。

### 3.3 【序幕爆过的内容，后续幕次绝不重演】
- **背景**：某东南亚绑架案项目和某抚养欺诈案项目均出现此问题。
- **教训**：序幕已经用最大冲击力爆出核心事件（被卖/被绑/亲子鉴定结果），后续幕次再演同一事件 = 重复，用户直接否"第二幕不是和序幕重复了？"
- **正确做法**：序幕爆完结果，后续幕演**新信息**——如主角起诉 + 对方反扑 + 群像受害者对话等，不能把序幕的事件换个角度再演一遍。

### 3.4 【序幕死亡动作链必须完整呈现】
- **背景**：某网络暴力/追星悲剧项目，用户问"真实的话是不是吃完药后又坐着上吊"。
- **教训**：受害者死亡动作按真实报道全链呈现（服药饮酒 → 绳索自缢两步都要），不能只写一半。
- **正确做法**：对动作链存疑先查证再动笔（资料阶段查原报道的动作顺序），确认后完整呈现，不删减不合并。

### 3.5 【尸体处置 = 画面收束，黑屏一行字压住】
- **背景**：某东南亚绑架案项目，用户指定"最后把尸体扔海里了"。
- **教训**：撕票不演暴力画面，用处置过程 + 自然音效收幕。
- **正确做法**：套进黑袋 → 拖走 →（闷喊"不要……求求你们……"）→ 切夜海船景 → 黑袋推进海"扑通"水花 → 水面恢复平静 → 黑屏一行字（"某年某月，某海域"）。水花 + 平静 = 压抑到顶，观众跟着坠底。尸体处置段属于"核心事实外可重组的外围细节"（媒体未披露真实抛尸方式），海域地点为剧本设定，忠于"撕票 + 抛尸"定性即可。

## 四、故事线设计类

### 4.1 【不用纪实平铺，序幕要用动作 + 悬念钩子】
- **背景**：某抚养欺诈案项目，第一版故事线按纪实时间线平铺——序幕 = 鉴定后对峙戏、幕 1 = 闪回 8 年幸福，用户直接否"你这设计的还是不够吸引人啊"。
- **教训**：纪实平铺无效。对峙戏如果只是"妻子嘴硬"不够炸，温水闪回更无效。
- **正确做法**：三原则——
  - ① **序幕不用平铺对话，用动作 + 悬念钩子**：如深夜刷到相关新闻 → 偷剪熟睡女儿指甲验 DNA → 被妻子撞见"大半夜你干嘛""她指甲长了"——开屏即毛骨悚然
  - ② **幕 1 不用温水闪回，用质问戏**：如三连问"监控呢？""坏了。""行车记录仪呢？""也坏了。"——骗局操作全在两句对话里
  - ③ **金句前置 + 每幕设炸点**：核心金句从正文前置到对峙顶点；每幕都要有一个炸点
- **设计完自检两问**：序幕 3 秒内震不震得住？每幕有没有一句能截图的台词？

### 4.2 【序幕要"核弹直爆"，悬念钩子还不够】
- **背景**：某抚养欺诈案项目，故事线迭代第二轮被否"不行，每一幕稍微加长点，序幕要更炸裂，把检测结果这些都爆出来"。
- **教训**：悬念钩子（偷剪指甲）还不够炸。用户要的是开屏直接砸结果。
- **正确做法**：序幕从"悬念钩子"升级为**"核弹直爆"**——如四份报告摔桌上，第一句台词"三个孩子，没有一个是我亲生的"，把检测结果/骗局操作/嘴硬金句全砸出来。每幕行数从 6-8/10-15 放宽到 12-14/15-18（用户明确要求加长时，SOP 的行数上限让位于用户指示）。

### 4.3 【主角必须有反击弧线，观众要看得爽】
- **背景**：某抚养欺诈案项目，故事线迭代第三轮被否"剧本要写的观众看得爽"。
- **教训**：如果主角只是被动受苦，观众看得压抑但没有爽感，不符合短剧需求。
- **正确做法**：设计完整的反击弧线——崩溃 → 觉醒（起诉）→ 守底线 → 当庭回怼。爽点 = 金句对轰（如"你生她们的时候，怎么没想过她们怎么做人？"）、守底线（"养，我认。法院，我去。她欠我的，一分别想少。"）、当庭回怼（"孩子是我的？那你养。""这钱，你该还。"）、索赔金额砸出来。

### 4.4 【幕 3"心软/撤诉"类转变必须有理由】
- **背景**：某抚养欺诈案项目，故事线迭代第三轮被否"第三幕转变得没啥理由"。
- **教训**：主角突然心软没有铺垫 = 转变无说服力。
- **正确做法**：不是主角自己心软，是被全家 + 孩子逼着软——如奶奶施压 + 父亲坦白"我早看见了，没敢说"（共犯之刀）+ 大女儿哭问"爸爸，你是不是不要我们了？"（最重一刀）——但守住底线，转变 = 被逼着软但不放弃反击。

### 4.5 【幕 4 必须让观众"看得懂"，单场景收束】
- **背景**：某抚养欺诈案项目被否"第四幕我没看懂，啥玩意"；某东南亚绑架案项目被否"幕 4 整体是不是在灌水"。
- **教训**：最后一幕如果用抽象法庭戏或多场景群像罗列，观众看不懂/觉得灌水。
- **正确做法**（两条规则合一）：
  - **抚养欺诈类**——顺序固定：当庭宣读司法鉴定实锤 → 对方仍嘴硬 → 主角回怼 → 当庭陈述索赔金额 → "休庭，择期宣判" → 画面收束 + 字幕。
  - **绑架/施暴类**——**只留一个场景**，把"三年后/真相落地/凶手逍遥"全部融进该场景的道具和动作，**禁止群像罗列**。定稿结构：收尾必须落在施暴者身上——施暴者刷手机看到热搜"确认遇害"+ 评论区"一路走好"→"看，三年了，没一个人知道是我"（毫无悔意）→ 秒点开新猎物头像发同样的诱骗消息（**和骗死者的台词一字不差 = 循环已开始）→ 镜头下移桌上摆着新猎物合照（她是连环的，不是偶发）。最压抑的结尾 = 凶手逍遥 + 已经在骗下一个。被砍掉的灌水段：社媒运营群像、诱骗者销号段、主犯遣返新闻播报段——这些信息观众自己脑补更快。

## 五、剧本格式类

### 5.1 【剧本输出格式 = 章节名一级标题 + 正文纯文本，禁表格/加粗/引用】
- **背景**：某东南亚绑架案项目，用户贴某追星悲剧项目剧本作参考格式纠正；后续某医生题材项目，用户明确要求"序幕/第一幕变成一级标题"。
- **教训**：交付的剧本正文是**纯文本**；章节名必须用一级标题（`# 序幕` / `# 第一幕`），不能裸写"序幕"两字，也不能用其他标题层级。
- **正确做法**：
  - 开头**金句引言两行**（无标题，点题用，如"你把真心捧给她，她把你明码标价。\n两个字，是这世上最好听的骗局。"）
  - 然后直接"# 序幕\n场景：地点，时间\n（动作描写。）\n角色名：台词"——**章节名（序幕/第一幕/第二幕…）用一级标题，下一行直接"场景：地点，时间"，不留空行**，场景切换同样直接换行写"场景：xxx"（不空行）
  - 台词格式 `角色名：台词`，动作/画外音/镜头提示用（括号），电话那头/字幕/弹幕评论也照此处理
  - 正文禁 markdown 表格、加粗、引用块、列表符号；**除章节名外的任何位置都不允许出现 # 标题符号**；剧本文件本身是 .md 但内容按纯文本写

### 5.2 【网友评论/弹幕必须用真实的，禁 AI 编造】
- **背景**：某东南亚绑架案项目，用户原话"很多网友的评论都用真的，不需要 AI 生成"。
- **教训**：编造的网评没有真实感，观众一眼看穿。
- **正确做法**：评论区/弹幕使用真实的热搜梗/真实评论区留言（如"一路走好""防火防盗防闺蜜"等），在资料收集阶段就搜集真实评论备用。

### 5.3 【人物名策略：剧内用知名度高的称呼，真名只在角色表 + 结尾字幕各留一次】
- **背景**：某东南亚绑架案项目，用户要求"把真名改为知名度更高的称呼"。
- **教训**：全剧统一用观众认知度高的称呼，家人称呼也统一；真名只保留在两处——角色表注明 + 结尾字幕官方定性句，忠于事实必须带真名。
- **正确做法**：全剧统一用一个称呼；角色表标注本名；结尾字幕写"官方确认 XX（本名）已于某年遇害"等定性句。绑定匪点名用高认知称呼更炸。

### 5.4 【防封改名：真实人物名必须改为近似防封名】
- **背景**：某网络暴力/追星悲剧项目，用户主动要求。
- **教训**：AI 短剧发布平台会对真实当事人姓名限流/封禁。
- **正确做法**：S4 剧本交付前，真实人物名必须改近似防封名（如原名 → 近似发音的化名）。资料区注明"真实原型为 XXX"便于溯源，新闻链接保留原名。**不是可选优化，是交付标配。**

### 5.5 【角色名管理：全文角色名要少而统一】
- **背景**：某网络暴力/追星悲剧项目，用户"名字怎么那么多，太乱了吧"。
- **教训**：同一个人用多个称呼（全名/英文艺名/昵称混排）= 观众混乱。
- **正确做法**：
  - 同一个人只用 1 个称呼，禁全名/英文艺名/昵称混用
  - 路人角色无名化（"成员"）
  - 粉丝群/群众角色用编号（"粉丝 A/B"）且跨幕复用（第四幕可复用第二幕的粉丝 A，不新开 C）
  - 全文角色名 ≤ 3 个
  - 改法示例：第一幕"帮我把花递给某角色"→"帮我把花递给他"（用代词减少名字出现频率）

## 六、资料核验类

### 6.1 【初步资料可能不在标准位置】
- **背景**：多个项目实测已成规律（职校实习压榨案、追星悲剧案、东南亚绑架案等）。
- **教训**：标准位置（如"初步资料.md"）可能缺失，实际素材在"参考资料\"目录下。文件格式可能是：①带序号的主题文件 ②完整事件报告 ③泛财经文案成稿（即文案线已完成的稿件，剧本线直接以它为输入）。
- **正确做法**：S0 阶段先核对项目目录，确认哪个文件是初步资料，向用户问一句"这个参考资料就是初步资料吗"，不默认跳过、不擅自拿参考资料当初步资料。

### 6.2 【参考文案 ≠ 初步资料，要区分两者】
- **背景**：参考资料目录下的文件类型混杂。
- **教训**：参考资料可能是泛财经风格的参考文案（带封面/标题/字数建议批注），不等于初步资料；也可能是 AI 整理的事件报告（带 AIGC 头注释/免责声明），报告本身可当初步资料用。
- **正确做法**：区分文件类型后决定使用方式。**文案成稿的数字/人名/定性仍须权威源复核，不能直接抄**（实例：成稿写"500 多万赎金"→ 官方口径约 80 万美元 ≈ 540 万人民币；主犯网传多名并存待核勿混）。

### 6.3 【社交媒体/社区高赞内容是关键细节富矿，但核心事实必须权威源核验】
- **背景**：多个项目实测。核心事件的关键细节（如监控时间、底薪金额、请假需医院证明）常来自社区高赞回答。
- **教训**：社区内容可信度标注为中等，作线索不作事实。写进资料卡前必须用权威媒体（官方通报/主流媒体/百科/官方文件）交叉验证。
- **正确做法**：社区内容 = 线索来源，用来发现细节方向；权威源 = 事实依据，用来确认细节真伪。两步分开，不可合跳。

### 6.4 【数字必须带时间/单位/来源，防止糅合时串数据】
- **背景**：多案例糅合项目，不同案例的数字容易混淆。
- **教训**：如"12 小时/天、底薪 1900、单休"（某年事件）vs"底薪 1300、早 7:30 到晚 8 点"（另一年事件）——每个数字必须核验归属案例和时间。
- **正确做法**：资料卡里每个数字标注：数值 + 单位 + 时间 + 来源案例。糅合时逐项核对，防止 A 案例的数字写到 B 案例头上。

### 6.5 【搜索渠道策略与限流应对】
- **背景**：多项目实测，不同搜索工具有各自的特点和限制。
- **教训**：单一搜索渠道连续使用后会限流（如搜索引擎连续约 4-5 次后返回异常），影响资料收集效率。
- **正确做法**：
  - 搜索引擎为主，社交媒体搜索/社区搜索为辅，网页抓取工具处理特定页面
  - **交替使用不同渠道**，天然错开限流（如搜索引擎与社区/英文渠道交替）
  - 社区平台深度帖/盘点帖（如"案件名 + 补档/盘点/如何看待"）可一次获取全国案例全貌 + 历案金句，比逐案搜索快 10 倍
  - 跨国/国际事件用英文搜索效果更好（多源交叉验证主事件）
  - 限流时切换到备用渠道，不卡在单一渠道上反复重试
  - 系列案（跨省同类型案件）优先搜盘点帖获取全貌

## 七、其他

### 7.1 【反派"可恶感"强化：用动作 + 反差，不靠解说】
- **背景**：某网络暴力/追星悲剧项目，用户主动要求强化施暴者方的戏。
- **教训**：施暴者方的戏如果只有对话没有动作，"可恶感"不够强。
- **正确做法**：偶像/施暴者方的戏要加轻蔑动作实锤嘴脸——如"刷到受害者自杀热搜 → 划过去 → 嗤笑一声 → 收起手机上台"式处理（真实事件 = 惨剧发生后照常登台 + 笑称"我很幸福"）。用动作 + 反差让观众恨，不靠解说。

### 7.2 【同主题案例库可复用，别重搜】
- **背景**：同一类型的选题（如网络暴力/追星悲剧、职校实习压榨、抚养欺诈、东南亚绑架等）在不同项目中反复出现。
- **教训**：每次新项目都从头搜索浪费时间，已有项目的资料收集成果可直接复用。
- **正确做法**：同主题新项目启动时，先检查是否有已有项目的案例库/资料卡可复用。核心主事件的细节数据仍须重新核验（防止旧数据过期），但同类案例的素材可直接调用做字幕串联/局部糅合。

### 7.3 【序幕设计完自检两问】
- **背景**：通用自检方法，适用于所有项目的序幕设计。
- **教训**：设计完不自检就提交，经常被否"不够吸引人"。
- **正确做法**：序幕设计完后自检——①序幕 3 秒内震不震得住？②每幕有没有一句能截图的台词？两个都答"有"再提交。

### 7.4 【反派不能降智：打脸靠程序/证据链，反派要"自以为占理"】
- **背景**：某跨国婚姻诈骗项目，用户反馈"感觉有点降智"——反派当众自爆、揭穿靠巧合（如"Airbnb退房留念"开天眼式暴露）。
- **教训**：把反派写成蠢货 = 打脸没有快感。反派当众自爆 = 观众觉得"这也太假了"，爽感崩塌。
- **正确做法**：
  - **打脸靠程序/证据链**：揭穿必须走真实可信的路径（法律程序、单据证据、时间线对不上），不是靠巧合/自爆
  - **反派要"自以为占理"**：他每一步都觉得"我没错/我聪明/我赢了"，越理直气壮，被打脸时越爽
  - 自查：删掉"巧合揭穿"场景，问自己"这个反派按他的逻辑会怎么做？"——他应该更谨慎，不是更蠢
  - 观众要的是"他这么聪明还是栽了"，不是"他是傻子当然会输"

### 7.5 【题材定调必须S0先问：爽剧还是纪实】
- **背景**：某跨国婚姻诈骗项目，用户要"艺术夸张让普通人爽"，AI 却先来一段"信息失真题"理性分析，方向直接跑偏。
- **教训**：同一个事件可以走爽剧（艺术夸张、打脸解气）也可以走纪实（信息失真、严谨还原），不先问清楚就动笔，必然写错方向。
- **正确做法**：**S0/S1 阶段必须先问用户题材定调**——"这次走爽剧（艺术夸张、让普通人爽）还是纪实（还原真实、不夸张）？"确认后整个剧本按该口径执行。爽剧可以放大冲突、夸张反派；纪实必须克制、忠于信息。

### 7.6 【支线控制：全剧单线为主，支线必须服务主线】
- **背景**：某跨国婚姻诈骗项目，用户要求"第二幕围绕丽华，换掉支线"——AI 设计的支线冲淡了主线。
- **教训**：短剧时长极短，支线一多主线就散。观众记不住 3 条线。
- **正确做法**：**全剧单线推进**（主角一个人的困境为主轴）。支线只允许两种：①服务于主线推进（如配角的证词/助攻）②用于情绪对照（如另一个受害者的同款遭遇）。任何"展开了但没回收"的支线=砍掉。设计故事线时自查：每幕是不是都打在主线上？有没有哪幕在讲"别的事"？

### 7.7 【法律/身份类事实也要权威核验，不只案例数据】
- **背景**：某跨国婚姻诈骗项目，剧本出现"绿卡=入籍""中国公民回国要签证"等法律硬伤，被用户当场指出。
- **教训**：AI 短剧常见错误——把影视剧里的模糊印象当事实。身份/国籍/法律程序类细节（绿卡与入籍区别、签证要求、司法流程）一旦写错，懂行的观众立刻出戏，甚至引发举报。
- **正确做法**：**所有身份/国籍/法律程序类事实必须权威源核验**（政府官网、法院文书、移民局政策），不许凭常识猜。S2 资料收集阶段专门加一项"法律/身份类事实核验"，写进剧本前逐条确认。拿不准的宁可模糊化处理（不写具体法律条文），不写错。
