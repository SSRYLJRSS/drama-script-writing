# SOP 全流程（S0→S7）

> AI短剧剧本撰写全流程操作手册。自包含，无需外部文件。

---

## S0：接收初步资料

### 用户输入方式
| 方式 | 处理 |
|------|------|
| 初步资料.md（事件描述+方向要求） | 最理想。读取后进入S1 |
| 只给一个事件名/新闻链接 | 先搜索事件全貌，自行建初步资料 |
| 给明确方向（"以XX为主，加其他案例"） | 选题已确认，可直接进S2 |

### 选题铁律
1. **只写真实事件**：不编故事。事件本身必须有强冲突、有社会争议
2. **以实事为主**：事件正在发酵或刚出结果时写，凉了不碰
3. **多爆点全前置**：序幕把最大冲击力的一幕直接甩出来

### 项目目录（S0阶段立即创建）

```
{项目工作目录}/
├── 初步资料.md                # 用户提供，不可修改
├── 资料收集/{案例名}/         # AI搜索后保存的详细资料
├── 故事线/故事线.md           # S3产出
└── 剧本生成/剧本.md           # S4产出
```

### 关键信号识别
| 用户说的 | 意思 |
|----------|------|
| "以XX为主，再加一些其他事件" | 选题已确认，直接进S2，不再等确认词 |
| "顺便把主题想出来" | 合并S1和S2 |

## S1：发散搜索与选题

### 输出要求（写死）
- **双输出**：①保存到本地 `项目目录/选题卡.md` ②对话中输出完整选题卡
- **停下等确认**：输出后必须停，等用户选定方向，禁止直接进入S2

### 核心规则
- 基于初步资料，发散搜索至少**5-8个不同案例**
- 每个案例提取：事件全貌、核心矛盾、戏剧亮点、冲突点
- 按"冲击力×可改编性×社会共鸣度"打分
- 输出选题卡，等用户确认

### 选题标准

| 维度 | 要求 |
|------|------|
| 真实性 | 必须基于真实事件 |
| 时效性 | 事件正在发酵或刚出结果 |
| 冲突烈度 | 有强对抗（施暴vs受害者、制度vs个体） |
| 社会共鸣 | 普通人能代入 |
| 可改编性 | 有具体对话场景和动作 |

### 选题四问

| # | 问题 | 判断标准 |
|---|------|----------|
| 1 | 冲突在哪？ | 有没有"凭什么"的差距 |
| 2 | 观众为什么在意？ | 能否代入 |
| 3 | 有具体场景和对话吗？ | 至少2-3个可改编为对话的真实细节 |
| 4 | 有社会争议吗？ | 规则/制度/观念层面的矛盾 |

少于两项成立不做。

### 事件类型识别

| 类型 | 特征 | 结构方向 |
|------|------|---------|
| 施暴-毁灭型 | 一方施压→另一方崩溃 | 序幕=崩溃时刻 |
| 罗生门型 | 双方各执一词，真相模糊 | 多视角切换 |
| 制度失效型 | 个体被制度碾压 | 踢皮球链条+绝望曲线 |
| 集体失败型 | 一群人想做件事，死于内部矛盾 | 群像+分裂过程 |
| 漠视型 | 施暴者不觉得自己在施暴 | 压抑到底 |
| **讴歌型** | **伟人/英雄/正能量，时代做反派** | **反差驱动：牺牲→坚守→迟到的敬意→功成字幕** |
| 反转型 | 装逼者被打脸，弱者翻盘 | 铺垫→打脸那一秒 |

### 选题卡模板

```markdown
## 主题定义
- 主题：
- 核心矛盾：
- 事件类型：
- 不写边界：

## 案例素材表
| 案例 | 事件全貌 | 核心矛盾 | 戏剧亮点 | 冲突点 | 冲击力 | 可改编性 | 社会共鸣 | 总评 |
|------|---------|---------|---------|--------|--------|---------|---------|------|

## 推荐写作方向
1. {方向1}（基于案例X）
2. {方向2}（揉合案例X+Y）

## 需要确认
是否按此方向进入资料收集？
```

### 选题卡确认问题（固定两个）
1. **主线**=单案骨架+糅合方向
2. **叙事视角**（受害者视角/家属视角/混合）

> **搜索技巧**：跨省系列案搜"案件名+补档/盘点/如何看待"，一条盘点帖可拿全国案例全貌。权威源优先官方通报/权威媒体。社交平台内容仅作线索，不作事实。

## S2：资料收集与冲突点提炼

### 输出要求（写死）
- **双输出**：①资料卡保存到 `项目目录/资料收集/{案例名}/` ②输出冲突点提炼表+资料覆盖表
- **停下等确认**：输出后必须停，等用户确认进入S3

### 搜索策略

**多轮搜索（从宽到窄）**：
| 轮次 | 策略 | 示例 |
|------|------|------|
| 第1轮 | 主题+通用词 | "小孩跳楼 学习压力 父母 新闻" |
| 第2轮 | 具体事件名 | "武汉某校 张某锐 扇耳光 跳楼" |
| 第3轮 | 细节关键词 | "张某锐 监控 走廊 三分钟" |
| 第4轮 | 同类案例 | "学生跳楼 遗书 妈妈我爱你" |
| 第5轮 | 判决/结果 | "冒名顶替罪 判决 刑法" |

### 搜索维度（至少覆盖5个）

| # | 维度 | 用途 |
|---|------|------|
| 1 | 事件全貌与时间线 | 还原"发生了什么" |
| 2 | 具体细节与数据 | 剧本对话的弹药 |
| 3 | 当事人行为与台词 | 角色对话原型 |
| 4 | 判决/官方回应 | 结尾字幕素材 |
| 5 | 同类案例 | 糅合素材+字幕串联 |

### 来源优先级
1. 官方通报、法院判决书
2. 权威媒体原始报道
3. 当事人公开表述（遗书、社交媒体、采访）
4. 深度调查报道
5. 社交平台内容（仅作线索）

### 冲突点提炼（S2核心产出）

从资料中提取可直接用于剧本对话的具体细节：

| 类型 | 说明 | 示例 |
|------|------|------|
| **数字冲突点** | 具体数字，直接写进台词 | 月入4000、补习费2800、英语53分 |
| **动作冲突点** | 具体行为，写在括号里 | 扇耳光、掐脖子、戳额头 |
| **台词冲突点** | 当事人真实说过的话 | "为你好""不考零蛋就行" |
| **场景冲突点** | 具体地点和时刻 | 五楼走廊3分钟沉默 |
| **反差冲突点** | 期望vs现实的落差 | 遗言是道歉不是控诉 |

### 资料卡格式

```markdown
# {编号}-{短标题}
- **事件**：{一句话}
- **时间**：{年月日}
- **来源**：[{媒体标题}]({完整URL})
- **可信度**：⭐⭐⭐⭐⭐ 官方/判决 | ⭐⭐⭐⭐ 权威媒体 | ⭐⭐⭐ 普通媒体
- **关键细节**：
  - {细节1}
  - {细节2}
- **可用于**：{序幕/对话/场景/结尾字幕}
```

### 核心约束
- 关键数字交叉核验：至少2个独立来源
- 只1个来源=待核验，不许进故事线
- 口径冲突以官方数据为准
- **社交平台内容仅作线索，不作事实证据**
- 数字必须带时间/单位/来源
- **法律/身份类事实专项核验**（写死）：剧本涉及国籍/签证/绿卡/入籍/司法程序/法律条文时，必须用政府官网、法院文书、权威政策源核验，不凭常识猜。拿不准的模糊化处理，不写错（见Pitfall 7.7）

## S3：故事线设计

### 输出要求（写死）
- **双输出**：①保存到 `项目目录/故事线/故事线.md` ②对话中输出完整全文
- **贴全文铁律**：每一版故事线（含修改版）都必须**完整贴出全文**（序幕+全部幕次+字幕+设计说明），禁止只贴改动摘要/片段。用户确认的是"看得见的全文"，改一处也要整版输出（见Pitfall 1.2）
- **停下等确认**：输出后必须停，等用户确认进入S4。**S3确认前禁止提及S4、禁止问"要不要开始写剧本"**

### 执行
1. 确定幕数（4-5幕，复杂事件可到6幕）
2. 设计每幕：场景+核心冲突+功能
3. 设计序幕：全剧最大冲击力的一幕
4. 设计结尾：画面收束方式
5. 确定哪些案例揉进故事，哪些放结尾字幕
6. 输出故事线，等用户确认

### 幕结构模板

| 幕次 | 功能 | 行数 |
|------|------|------|
| 序幕 | 最大冲击力前置，**加长演足** | 15-20行 |
| 第一幕 | 展开核心冲突 | ≤20行 |
| 第二幕 | 场景转换，加码/深化 | ≤20行 |
| 第三幕 | 反转/深化/收束 | ≤20行 |
| 第四/五幕 | 结尾压住 | 5-15行 |

### 序幕设计原则
1. **闪前优先**：把结局或最惨的一幕放到序幕
2. **一句话钩子**：序幕第一句台词必须携带核心矛盾
3. **不铺垫**：序幕只需要被震住
4. **可以闭环**：序幕画面在最后一幕重复出现

### 幕次排列逻辑（系统性之恶事件）

**核心原则**：先让观众愤怒于"系统怎么运作"，再看个体被碾压。

```
序幕  结局前置（毁灭瞬间，台词携带反差暴击）
  ↓
第一幕  系统性之恶（产业链分赃、规则制定者如何害人）
  ↓
第二幕  群像受害（用学生/同事间对话展示群体受害）
  ↓
第三幕  个体被压（主角求救被拒，观众已愤怒再看个体最痛）
  ↓
第四幕  最亲的人补刀（家长/伴侣"为你好"的施压）+ 结构回环
```

**反面教训**：不要把个体冲突放第一幕——系统之恶还没建立，观众还没愤怒，个体悲剧没有根基。

### 讴歌型幕次排列逻辑（伟人/英雄/正能量题材）

**核心原则**：先让观众看见"时代有多难、代价有多大"，再看主角怎么接住，最后释放迟到的敬意。

```
序幕  反差暴击（主角最狠的牺牲/最重的话用最轻的口气说出来）
  ↓
第一幕  时代之难（一穷二白、死亡率逼近100%、无药无械——反派是时代）
  ↓
第二幕  坚守与牺牲（主角对抗时代：救一个是一个，代价砸在自己身上）
  ↓
第三幕  被辜负/被低估（主角的坚持不被理解、被反对、被时代碾过——敬意还没来）
  ↓
第四幕  迟到的敬意（多年后数据说话：10张床→1.2万医师；主角的无所谓=情绪峰值）+ 功成字幕
```

**讴歌型序幕设计**：不用"悲惨结局前置"，用**"轻描淡写的牺牲"前置**——主角在生死关头说出最重的话，口气最轻（"就我自己孩子，我就拿他一下子吧"）。观众瞬间被反差震住，想知道"这人是干嘛的"。

**讴歌型结尾**：必须"功成"。字幕串联真实数据（死亡率90%→30%、10张床→1.2万医师、存活率20%→70%），最后一句话是致敬不是质问。不许泄气，不许说教。

### 糅合原则

| 可以揉合 | 不可以揉合 |
|---------|----------|
| 不同案例的具体细节 | 改变核心事件的事实经过 |
| 不同案例的冲突点重组到不同幕 | 混淆不同案件的法律结果 |
| 结尾字幕串联多个案例 | 把不同案例的当事人混为一个角色 |

**糅合后必查**：
1. 时间线一致性
2. 人物动机一致性
3. 因果逻辑不断裂

### 结尾模式

| 模式 | 用法 |
|------|------|
| 画面收束 | 用一个镜头画面结束 |
| 黑屏字幕 | 真实案例串联+最后一句话点题 |
| 角色台词收束 | 最后一句台词点题 |
| 沉默收束 | 所有角色沉默，画面停留 |

### 故事线模板

```markdown
# {剧本名} 故事线

## 核心矛盾
{一句话}

## 事件类型
{类型}

## 糅合来源
| 故事线元素 | 来源案例 |
|-----------|---------|

## 糅合后因果链条检查
- 时间线一致性：{检查结果}
- 人物动机一致性：{检查结果}
- 因果逻辑闭环：{检查结果}

## 分幕设计
### 序幕
- 场景：
- 核心冲突：
- 行数预估：15-20行

### 第一幕
- 场景：
- 核心冲突：
- 新信息：
- 行数预估：≤20行

### 第X幕（尾声）
- 场景：
- 收束方式：
- 字幕内容：

## 结尾字幕
1. {案例1}——{一句话}
2. {案例2}——{一句话}

## 需要确认
是否按此故事线写剧本？
```

## S4：写剧本

### 输出要求（写死）
- **双输出**：①保存到 `项目目录/剧本生成/剧本.md` ②对话中输出完整全文（禁只贴片段）
- **交付前强制自检（写死）**：剧本写完先**自己跑一遍S5终检清单**（降智检查/逻辑硬伤/行数/格式/伏笔/事实），发现问题当场修，修完再交付。**不许等用户喊"自检"**——交付的就是自检后的版本
- **停下等确认**：输出后必须停，**不主动进入S5**（等用户说"自检"或"修改"）

### 写作顺序

**第1步：写序幕（15-20行，加长演足）**
- 全剧最大冲击力的一幕，演足动作三连击，不让观众一眼扫完
- 第一句台词必须携带核心矛盾
- 不铺垫，不解释背景
- 可以用闪前

**序幕检查**：
- [ ] 第一句台词能抓住人吗？
- [ ] 观众看完序幕想知道"为什么"吗？
- [ ] 有没有铺垫句？（有就删）

**第2步：逐幕填充（每幕≤20行）**

| 规则 | 正例 | 反例 |
|------|------|------|
| 一人一句 | "英语53""妈，我已经很努力了" | 母亲一口气说五句话 |
| 每句都是点 | "一个月4000，交2800补习费" | "你要好好学习" |
| 口语化 | "不考零蛋就行" | "你的成绩还有很大提升空间" |
| 允许粗口 | "跟你爸一个德行" | 无情绪的平铺直叙 |
| 短句为主 | "妈""嗯""不该打牌" | 角色完整表白一段话 |
| 有权力方向 | 母亲追问"错哪了"、小锐回避"不该打牌" | 两人平等地各说各话 |

**第3步：写结尾（5-15行）**
- 画面收束或一句话点题
- 黑屏字幕串联真实案例
- 不说教不总结

**第4步：写资料区**
- 列出剧本涉及的真实案例
- 每个案例附新闻链接
- 核心事实、判决结果保持原封不动

### 生成硬约束
- **序幕 15-20 行，每幕不超过20行**
- **每句台词携带信息**（数字/动作/规则/关系/后果）
- **一人一句快速交锋**
- **场景描写压到最少**（括号里几个字）
- **每幕换一个场景**

### 禁止
- 禁止自言自语/旁白叙述/大段独白（角色一口气说超3句）
- 压抑型：禁止温情线（道歉、被安慰、送水等缓和时刻）、禁止美化死亡、禁止控诉式遗言
- 讴歌型：禁止说教结尾、禁止宣传稿腔（歌功颂德堆形容词）、禁止泄气结尾；温情线是主菜，必须保留
- 禁止说教结尾（所有题材通用）

### 剧本格式（章节名一级标题，正文禁markdown排版）

```
{金句引言第一行}
{金句引言第二行}

# 序幕
场景：{地点}，{时间}
（{动作描写}）
{角色名}：{台词}

# 第一幕
场景：{地点}，{时间}
（{动作描写}）
{角色名}：{台词}
...
```

- **章节名用一级标题 `# 序幕` / `# 第一幕`**，下一行直接"场景：地点，时间"
- 台词格式 `角色名：台词`，动作/画外音/镜头用（括号）
- **正文禁**markdown表格/加粗/引用块/列表符号；除章节名外不再用任何标题层级

> **完整格式规范** → `references/script-format.md`

## S5：自检与修改

> **触发方式（写死）**：S4 写完剧本先自己跑一遍下面的清单再交付——**交付的就是自检后的版本，不等用户喊"自检"**。用户反馈降智/逻辑硬伤/伏笔没收 = 自检没到位，重跑清单。

### 自检清单

**A. 对话驱动检查**
- [ ] 每场戏有2个以上角色在对话？
- [ ] 没有自言自语？
- [ ] 没有旁白叙述？
- [ ] 没有大段独白？（角色一口气说超3句）
- [ ] 一人一句快速交锋？

**B. 信息密度检查**
- [ ] 每句台词都携带信息？
- [ ] 没有废话对白？
- [ ] 没有形容词堆砌？
- [ ] 用具体数字替代笼统描述？

**C. 幕结构检查**
- [ ] 序幕 15-20 行，每幕不超过20行？
- [ ] 每幕换一个场景？
- [ ] 没有重复说同一件事？
- [ ] 信息说完就切场景？

**D. 序幕检查**
- [ ] 序幕是全剧最大冲击力的一幕？
- [ ] 序幕第一句台词能抓住人？
- [ ] 序幕没有铺垫句？

**E. 情绪基调检查（按题材分）**
- [ ] 压抑型：没有温情线？没有美化死亡？没有控诉式遗言？压抑到底，没有出口？
- [ ] 讴歌型：反差到位？（牺牲越大越不当回事）反派是时代？迟到的敬意释放了？结尾功成，没有泄气？
- [ ] 反转型：铺垫够短，打脸那一秒够狠？
- [ ] 情绪峰值出现在结尾（压抑=最虐，讴歌=最燃）？

**F. 结尾检查**
- [ ] 是画面收束不是说教？
- [ ] 字幕串联的案例忠于事实？
- [ ] 观众能带着情绪离场？

**G. 事实检查**
- [ ] 核心事实忠于原事件？
- [ ] 法院判决/关键数据没有编造？
- [ ] 法律/身份类事实（国籍/签证/绿卡/司法程序）已权威源核验？

**G2. 反派与支线检查**
- [ ] 反派没有降智？（不自爆、不靠巧合揭穿，自以为占理，打脸靠证据链）
- [ ] 全剧单线推进？（支线都服务主线，无没收的支线）

**H. 格式检查**
- [ ] 剧本格式正确？（章节名一级标题，正文纯文本无markdown排版）
- [ ] 角色名统一？（全文≤3个角色名）

### 常见修改方向

| 用户反馈 | 原因 | 解法 |
|---------|------|------|
| "太拖沓了" | 幕太长/废话对白 | 砍到20行以内，序幕保15行以上 |
| "信息熵太低" | 台词没携带信息 | 每句加数字/动作/细节 |
| "太美好了" | 仅压抑型：有温情线 | 砍掉所有缓和时刻 |
| "太悲了/不够正能量" | 仅讴歌型：基调偏了 | 拉回反差+牺牲+敬意线 |
| "感觉降智" | 反派写蠢了/巧合揭穿 | 重写打脸路径为证据链，反派自以为占理 |
| "先别进S4"/"还没到那步" | AI跳步了 | 回到当前步骤，S3确认前禁提S4 |
| "要完整输出"/"贴全文" | 只给摘要了 | 完整贴全文（序幕+各幕+字幕+角色表） |
| "不行" | 整体方向有问题 | 回S3重新设计 |

## 用户改稿教训（S4写剧本前必读）

以下经验提炼自用户亲自改稿（初稿→定稿逐幕对比）。

### 教训1：序幕台词必须携带"反差暴击"
- ❌ "请假？拿医院纸质证明来"（单一冲突）
- ✅ "说好8小时一个月4000，现在一天11小时就开2200，请假就记旷工"（三重暴击一句话甩出）
- **规则**：序幕第一句台词至少携带两个反差数字对比

### 教训2：产业链揭秘前置到第一幕
- ❌ 产业链放第三幕（太靠后）
- ✅ 产业链放第一幕
- **规则**：如果有系统性之恶，必须前置。观众先愤怒于系统怎么运作，后续个体被压垮才有因果

### 教训3：分赃对话要算总账（大数字）
- 不只算单价差，要算总额

### 教训4：群像受害用学生/同事间对话
- 不用雇主/老师视角说教

### 教训5：个体冲突（请假/求救）放中后段
- ❌ 放第一幕（系统之恶还没建立）
- ✅ 放第三幕（观众已愤怒再看个体最痛）

### 教训6：家长施压必须充分展开
- ❌ 第二幕带过（一两句"忍忍"）
- ✅ 第四幕核心，展开5-6句，每句换一个施压角度
- **规则**：家长=最亲的人补刀，台词要多角度（学校权威→吃苦价值观→同辈压力→娇生惯养→别丢人）

### 教训7：结尾用结构回环（呼应序幕）
- ❌ 重写一遍跳河画面+字幕
- ✅ "又打了一个电话"呼应序幕→戛然而止→字幕

### 教训8：结尾点题用"向观众的质问"
- ❌ "活着的时候没人管。死了，倒想起公关了。"（评论员嘲讽）
- ✅ "谁来救救他们？"（直接质问观众）

### 教训9：施暴者自己说规则
- ❌ 老李/老赵讨论时提到毕业证人质
- ✅ 校长直接说："不听话我不给毕业证！"

## S6：自我学习

### 触发时机（写死）
**用户任何一次改稿/纠正/提要求后自动触发**——不依赖S5自检通过，不等用户主动喊。剧本交付后用户只要给出修改意见（太短/太长/降智/换掉/全部修复/要改成XXX），AI 改稿完成后**必须主动**执行 S6：对比初稿 vs 修改版 → 提取经验 → 写入经验库。

**经验快速升格通道（写死）**：用户说"全写入，改规则"/"以后就这样"/"以后要XXX" = 经验**直接升格进 references 正式规则**（按维度映射目标文件），不留 learnings 暂存。不靠重复验证凑数（题材几乎不重复，等3次验证=永远升不了级）。

### Step 1：读取已有经验
读取 `learnings.md`（与SKILL.md同目录），快速浏览当前积累的经验条目。

### Step 2：向用户索取完整修改版（写死）
输出以下提示：

> "剧本交付了。如果你后续手动改过了，请把**完整修改版**发给我——**序幕+各幕+结尾字幕+角色表**，改过哪部分就发哪部分的最终版，我会逐段对比差异，提取通用经验写进经验库，下次写得更接近你的要求。"

**用户可能的回应**：
| 用户说的 | 处理 |
|----------|------|
| 发来了修改版文本 | 进入Step 3 |
| "没改" / "不用了" | S6结束 |
| "下次再说" | S6结束 |
| "全写入，改规则" | **直接升格进 references**，跳过 learnings 暂存 |

### Step 3：逐段对比差异
拿到用户的**完整修改版**后（序幕+各幕+结尾字幕+角色表，改过哪里对比哪里），和AI初稿**逐段对比**：

1. **逐段对齐**：按幕顺序，找出用户改了哪些段、哪些台词
2. **分类差异**：
   - 📝 **删减类**：用户删了什么？（删掉的往往是AI多余的）
   - ➕ **新增类**：用户加了什么？（加的往往是AI缺失的）
   - 🔄 **改写类**：用户怎么改的？（同义换皮/换结构/换语气）
   - 💬 **台词类**：对话改了？可能AI的台词不够"点"
   - 🎬 **场景类**：场景/动作改了？
   - 📐 **结构类**：幕次/顺序调整？

### Step 4：提取通用经验
从差异中提取**通用规律**（不是个例）。

**判断标准**：
- ✅ 通用规律："AI写的序幕缺少反差暴击，用户改为携带两个数字对比" → 可写入
- ❌ 个例："这个序幕的'请假'改为'8小时4000'" → 不写入
- ✅ 通用规律："AI写的结尾用评论员嘲讽，用户改为质问观众" → 可写入
- ❌ 已有规则："每幕不超过15行" → 不写入

### Step 5：输出经验条目给用户确认

> "我从你的修改版中提取了X条通用经验：
> 1. [经验1摘要]
> 2. [经验2摘要]
> 要写入经验库吗？你可以说'全写入'、'只写入第X条'、或'都不写'。"

### Step 6：写入 learnings.md
用户确认后，将经验条目写入对应置信度区域：
- 高置信度区：验证3次以上
- 中置信度区：验证1-2次
- 低置信度区：仅1次（30天内未升级则删除）

**写入前检查**：
1. 与SKILL.md现有规则重复？→ 不写入
2. 与核心风格规则冲突？→ 标记"需讨论"
3. 是否具体可执行？
4. 是否是个例而非规律？

### Step 7：检查压缩条件
```
文件大小 > 5KB 或 条目数 > 30 → 执行压缩
```

### 压缩流程

| 状态 | 处理 |
|------|------|
| 低置信度 + 30天内未升级 | 删除 |
| 高置信度 + 已被SKILL.md吸收 | 删除 |
| 重复经验 | 合并为一条 |
| 模糊经验 | 改写或删除 |
| 仍然有效且未被吸收 | 保留 |

### 防偏移保障
1. **物理隔离**：learnings.md 独立于 SKILL.md
2. **写入前检查**：与核心规则冲突→标记"需讨论"
3. **用户审批**：所有写入必须用户确认
4. **定期压缩**：超阈值自动触发
5. **维度标注**：每条经验标维度（序幕/结构/对话/结尾/格式/流程）
6. **置信度分级**：低置信度自动过期

## S7：经验升级与文风变更（定期维护）

> **不是每个项目都走的步骤**。触发方式：
> - 定期：每完成10个项目 / learnings.md高置信度经验≥5条 → AI主动提醒
> - 手动：用户说"整理经验库" / "升级经验" / "以后文风要改XXX"
> - **快速通道**：用户说"全写入，改规则" → 立即执行模式A（不等攒够5条）

### 模式A：经验升级（learnings → references）

把 learnings.md 里高置信度经验"毕业"到 references 正式文件，然后清掉。

**目标文件对照表**：

| 经验维度 | 升级目标文件 |
|----------|-------------|
| 序幕/结尾写法 | `style-system.md` |
| 结构/幕次排列 | `sop-full-flow.md` |
| 对话/信息密度 | `style-system.md` |
| 改稿教训/Pitfall | `pitfalls-and-revisions.md` |
| 剧本格式/角色名/防封 | `script-format.md` |
| 流程/步骤规则 | `sop-full-flow.md`（或SKILL.md） |

**流程**：
1. AI扫描learnings.md高置信度区
2. 逐条评估：升级到哪个文件？怎么加？
3. 输出"升级方案"给用户逐条审批
4. 用户确认后AI修改对应references文件
5. 已升级的条目从learnings.md删除
6. 输出升级报告

### 模式B：文风变更（用户主动改规则）

**触发信号**：用户说"以后不要XXX"或"以后要XXX"

**流程**：
1. AI定位现有规则（在哪个references文件里）
2. 输出"变更方案"：旧规则 → 新规则，标注影响范围
3. 如果learnings.md里有与旧规则相关的经验 → 一并处理
4. 用户确认后AI修改对应文件
5. 记录到learnings.md的"变更日志"

**关键**：文风变更时如果与learnings.md现有经验冲突，必须一并清理——否则老经验会拉扯新方向。
